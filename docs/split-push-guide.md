# Publishing the split

Everything is prepared locally and nothing has been pushed. Run these in order, from this folder unless a step says otherwise. Each part leaves both sites working, so you can stop between parts.

Checked locally on 2026-11-02: OpVAL has 130 passing tests, VFL has 208 (338 in total, the same as before the split). Both builds and both `wrangler deploy --dry-run` runs pass.

## What you need first

| Thing | Where to get it | Used in |
|---|---|---|
| New `FEED_INGEST_TOKEN` | Generated by the command in part 2. Secrets can't be read back from GitHub or Cloudflare, so it's a fresh one. | Part 2 |
| Cloudflare account ID | `aec0c5bad8122dd16d17181216d23580` (from `npx wrangler whoami`) | Part 4 |
| Cloudflare API token | [dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens): Create Token, "Edit Cloudflare Workers" template, add the permission Account > D1 > Edit, then Continue and Create. Copy it; it's shown once. | Part 4 |

`GITHUB_DISPATCH_TOKEN` is already on the `opval` Worker and survives the rename. The `gh` and `wrangler` logins on this laptop are both working.

## Part 1: rename the repo and ship the ingest route

```bash
gh repo rename opval --yes
```

```bash

```

This commits only the three named files, leaving the rest of the split out:

```bash

Wait until "Deploy OpVAL" shows `completed success`:

```

## Part 2: move the feed to OpVAL

Run this as one block. It should print `{"ok":true}`. If it doesn't, stop here: the feed is untouched until the next line succeeds.

```bash
TOKEN=$(openssl rand -hex 32)
printf %s "$TOKEN" | npx wrangler secret put FEED_INGEST_TOKEN --config apps/call/wrangler.jsonc
sleep 15
curl -s -X POST https://opval.dimas.works/internal/ingest -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"schemaVersion":1,"kind":"heartbeat","runId":"manual-check"}' | tee /dev/stderr | grep -q '"ok":true' && gh secret set FEED_INGEST_TOKEN --body "$TOKEN"
```

```bash
git commit -m "Post the feed to OpVAL" .github/workflows/feed.yml
```

```bash
git push origin main
```

```bash
gh workflow run feed.yml
```

Wait for "Feed poll" to show `completed success`:

```bash
gh run list --workflow=feed.yml --limit 2
```

```bash

```

```

```

```bash

```

Wait for `completed success`, then check [vctfantasy.dimas.works](https://vctfantasy.dimas.works):

```bash

```

If this deploy fails, the site keeps running the previous version. Fix it in `vfl` and push again.

## Later: adding cards

1. Change cards in `cards-val/`, then commit and push.
2. In `opval/` and in `vfl/`, run `git submodule update --remote shared`, then commit `shared` and push. That push deploys the new cards.

To have GitHub open those update PRs daily, add a `.github/dependabot.yml` with the `gitsubmodule` ecosystem to each app.
